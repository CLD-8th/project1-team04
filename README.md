# 도메인·기능 정의서 — 중고거래 게시판

## 1. 서비스 개요

| 항목 | 내용 |
| --- | --- |
| 한 줄 정의 | 사용자가 중고 물품을 게시·조회하고, 판매자에게 거래를 신청하는 서비스 |
| 대상 사용자 | 개인 판매자와 구매자 |
| 서비스 지역 | 국내 (리전: ap-northeast-2 서울) |

## 2. 핵심 기능

### 기능 1. 상품 등록, 목록 및 상세 조회
- 판매자가 제목·설명·가격·카테고리·사진 1장을 입력해 상품을 등록한다.
- 구매자는 카테고리·판매 상태로 목록을 조회하고, 상세 페이지에서 상품 정보와 거래 상태(판매중·판매완료)를 확인한다.

### 기능 2. 거래 신청·승인 (거래 상태 변경)
- 구매자가 판매중인 상품에 거래를 신청한다.
- 판매자는 상품별 신청 목록을 확인하고 그중 하나를 승인한다.
- 승인 시 상품 상태가 **판매완료(SOLD)** 로 변경된다.

#### 상태 전이

| 이벤트 | deal.status | product.status |
| --- | --- | --- |
| 상품 등록 | - | SELLING |
| 거래 신청 | REQUESTED | SELLING (변화 없음) |
| 거래 승인 | APPROVED | SOLD |

- 판매자 본인은 자기 상품에 신청할 수 없다.
- 승인은 해당 상품의 판매자만 할 수 있다.
- SOLD 상품에는 신규 신청이 불가하다.
- 거래 취소는 범위 밖 (향후 확장).

## 3. Redis 활용 기능

| 항목 | 내용 |
| --- | --- |
| 기능 | 사용자별 최근 본 상품 최대 20개 (최신순) |
| 자료구조 | Sorted Set (score = 조회 시각) |
| 갱신 시점 | 로그인 사용자가 상품 상세를 조회할 때 |
| 만료 | 마지막 조회로부터 7일 (TTL) |
| 설계 반영 | cache 컨테이너 → **ElastiCache (Redis OSS)** |

상세 설계는 [redis-keys.md](redis-keys.md) 참고.

## 4. 파일 요소

| 항목 | 내용 |
| --- | --- |
| 종류 | 상품 사진 (png, jpeg) |
| 개수 | 상품당 1장 |
| 최대 크기 | 5MB |
| 조회 시점 | 상품 상세 조회 시 노출 |
| 저장 방식 | 로컬 볼륨(`uploads`)에 저장, DB에는 저장 키(`stored_key`)만 기록 |
| 설계 반영 | uploads 볼륨 → **S3** (stored_key를 S3 객체 키로 그대로 사용) |

## 5. 데이터 특성

| 항목 | 내용 |
| --- | --- |
| 주요 엔티티 | `users` · `products` · `deals` |
| 읽기 : 쓰기 | 9 : 1 (목록·상세 조회가 대부분, 등록·신청은 드묾) |
| 설계 반영 | 읽기 비중이 높음 → 최근 본 상품 등 조회성 데이터는 Redis 활용, 향후 읽기 전용 복제본 검토 |

| 항목 | 가정 수치 | 근거 |

| 피크 RPS | 1,000 ÷ 10 = **100 RPS** | |
| 급증 이벤트 | 주말, 인기 상품 등록 시 ×2 | |
| 급증 RPS | 100 × 2 = **200 RPS** | |
| 인스턴스 1대 처리량 | **100 RPS (가정)** | 실제 값은 k6 부하 테스트로 측정 후 조정 |
| Auto Scaling | 최소 2 · 희망 2 · 최대 3 | 최소 2는 AZ 이중화 조건, 최대 3은 200 ÷ 100 + 여유 1 |

## 7. 중요도

| 항목 | 목표 | 설계 반영 |
| --- | --- | --- |
| RTO | 30분 | 수동 복구로는 달성 어려움 → **RDS Multi-AZ 자동 장애 조치** (보통 1~2분) |

| 가용성 | 99.9% | 월 약 43분 중단 허용 → **2개 AZ + ALB + Auto Scaling** |
